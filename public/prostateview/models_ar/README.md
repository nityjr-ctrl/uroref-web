# ProstateView AR Model Optimisation

This folder is generated by `npm run optimize:ar`. It is intentionally separate
from `public/demo-cases`; the source GLBs are never edited in place.

## One-command run

Checkpoint run on the requested demo case:

```powershell
npm run optimize:ar -- --case pv-case-021
```

Batch run after clinical/visual approval:

```powershell
npm run optimize:ar
```

Human/anatomy palette batch:

```powershell
npm run optimize:ar:human
```

Both baked palettes:

```powershell
npm run optimize:ar:palettes
```

Build apex and oblique QA contact sheets after a batch:

```powershell
npm run optimize:ar:thumbs
npm run optimize:ar:thumbs:human
```

Useful options:

```powershell
npm run optimize:ar -- --case pv-case-021 --target-triangles 60000 --max-triangles 80000
npm run optimize:ar -- --case pv-case-021 --use-blender --blender "C:\Program Files\Blender Foundation\Blender 4.3\blender.exe"
```

## Pipeline

1. Decode the source Draco GLB to a temporary editable GLB using
   `gltf-transform copy`.
2. Inspect triangle count, vertex count, byte size, bounds and watertight mesh
   count.
3. Clean duplicate vertices, degenerate faces and tiny stray islands. Lesion
   meshes are protected from island removal.
4. Apply a conservative Taubin-style smooth. Default is only 3 iterations, to
   soften marching-cubes stair-steps without erasing real anatomy.
5. Decimate only when the anatomy exceeds the mobile budget. The default target
   is 60k anatomy triangles, with 80k as the upper gate before marker allowance.
6. Centre the pivot at the anatomy bounds centre and preserve metre scale unless
   the source is clearly not in metres.
7. Bake the AR default pose so apex (`A`) faces the default viewer/camera,
   with base (`B`) away from the viewer.
8. Apply the selected baked material palette: `teal` for the sleek
   ProstateView look, or `human` for the softer source-like anatomy colours.
9. Add baked A/B/L/R orientation markers, on by default, as `orientation_*`
   meshes.
10. Export GLB, then run `gltf-transform optimize` with Draco compression,
   welding, pruning and small textures.
11. Export USDZ when `usd-core` is installed.
12. Validate GLB, file size, triangle budget, USDZ presence and write
   `optimise_report.csv`.

## Triangle and size budgets

The working target is 30k-80k anatomy triangles per case. This is high enough to
preserve the gland, PZ/TZ and lesion surfaces from the Prostate158-derived
models, but low enough for smooth mid-range phone AR. Marker pins and labels add
a small fixed overhead.

The GLB size budget is under 2 MB per model. Most generated outputs should be a
few hundred KB because the meshes are Draco-compressed and texture use is limited
to four small orientation-label textures.

## Palettes

Two baked palette outputs are supported because mobile AR viewers do not reliably
support live material switching after the model is launched:

- `models_ar`: default `teal` palette. Neutral frosted gland, teal PZ, clear
  blue TZ and rose lesions, matching the ProstateView dark theme.
- `models_ar_human`: source-like `human` palette. Very translucent neutral
  gland, warm PZ, clearly blue TZ and stronger mauve lesions. Use this when the
  model should read more like a human anatomy teaching object in room-scale AR.

## Orientation convention for clinical review

The current ProstateView source GLBs use this canonical frame:

- `+X` = patient left, `-X` = patient right
- `+Y` = posterior, `-Y` = anterior
- `+Z` = base/superior, toward the bladder
- `-Z` = apex/inferior, toward the membranous urethra

For AR exports in this folder, the pipeline remaps the source axes into the
phone teaching frame:

- `+X` remains patient left, `-X` remains patient right
- `+Y` becomes anterior/screen-up, `-Y` becomes posterior/screen-down
- `+Z` becomes apex/front, so the default model-viewer/AR pose opens with
  `A` facing the viewer
- `-Z` becomes base/back, away from the viewer

A/B/L/R markers:

- `A` = apex/inferior, toward the viewer on initial load
- `B` = base/superior, away from the viewer
- `L` = patient left
- `R` = patient right

Patient left/right here are anatomical patient left/right, not screen left/right.
The patient left marker is `L`; patient right is `R`. In the default AR view,
patient right appears on screen-left and patient left appears on screen-right.

To toggle markers in a viewer, hide meshes/nodes named `orientation_*`. They are
kept on by default for AR handoff and visual QA.

## Blender

Blender is optional but supported. If installed, use `--use-blender` to run the
headless `scripts/blender_ar_cleanup.py` pass before the Python cleanup/export
stage. The script is intentionally conservative: merge by distance, delete loose
geometry, recalculate normals and apply a light smooth modifier.

Blender can use GPU acceleration for viewport/render work, but the exported AR
assets remain phone-sized and are not tuned for desktop-only performance.

## Clinical flags

This is a geometry cleanup and orientation pipeline, not a clinical validation
step. Cases with unexpected orientation, lesion laterality mismatch, unusual
scale changes, failed USDZ export or excessive decimation should be reviewed
manually before trainee use.
